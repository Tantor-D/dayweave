# v0.2.0 focus-workbench 技术方案

## 文档的关键结论

继续使用现有 React／TypeScript／Fastify 与 JSON／Markdown 真源，不引入新框架或存储。点击安排和玻璃视觉更新在现有前端模块内实现；标签领域迁移依赖分类边界确认，当前不修改持久化格式。

## 现状与授权

- 基线为本地提交 `aec7ed2`，开发前 main 工作区与暂存区干净，无 ROADMAP.md。
- v0.1.0 已有 Placement 多段排期、15 分钟吸附、跨日、横纵轴与统一保存历史；空白时间格尚无点击入口。
- 当前 Task 使用单选 priority P0–P3，分类由独立任务保存或从项目继承。用户明确要求将 P0–P4 改为普通预置标签，多选自定义标签；是否统一移除分类待确认。

## 模块改动

### 时间轴入口

- `Timeline.tsx` 将空白格点击位置转换为排期草稿，提供未定时入口。事件忽略已有任务元素；沿用拖拽后的点击抑制。
- `time.ts` 复用时区转换与吸附；不改变排期业务约束。
- 新增安排对话框组件，提供新建／关联选择、任务搜索与日期时间编辑。保留打开时的快照，调用 App 的 save 与既有规范操作。
- 新建使用明确任务 ID，task.create 与 placement.put 一起提交；关联只产生 placement.put。服务端仍负责校验、冲突、未定时去重和历史。
- 表单支持 Esc、焦点约束与返回触发点，提交期间禁止重复提交；失败显示错误，不自动覆盖新版本。

### 视觉

- 修改 ThemeDefinition tokens 与 App.module.css；保留 ThemeContext／ThemeCard／ViewLayout 扩展方式。
- 用原生 CSS 玻璃材质、系统字体和图标实现；不增加图片、字体网络请求或设计依赖。
- 明确前景与背景层次，固定内容区域避免文字透叠；浏览器不支持模糊或偏好减少透明度时采用实体表面。

### 标签迁移：待确认后补齐

确认后在本文件补齐 schemaVersion 迁移、旧工作区备份、历史旧快照恢复、提案失效、偏好筛选及 AI 工具契约。迁移不得静默丢失旧分类或覆盖未知文件；必须先检查 store 的启动恢复与历史校验路径。

## 验证

- 时间坐标测试覆盖起止边界、15 分钟吸附与跨午夜默认时长。
- 构建与现有全量自动测试验证保存、审批、冲突、历史、HTTP 与模拟 AI 不回归。
- 使用隔离数据目录在真实浏览器验证点击新建／关联、重复未定时、横纵轴、多日、拖动之后不误触、取消和刷新持久化。
- 检查深浅主题、窄窗与控制台；截图与验收记录只放 `.artifacts/` 等已忽略目录。
- 不调用真实模型，不将既有真实接口未验证状态变成通过。

## 实施结果

时间轴入口与视觉更新已实现，构建、56 项自动测试及隔离数据浏览器交互通过；包含新建／关联、去重、跨日、拖拽拉伸、键盘焦点与双窗口版本冲突。模态框直接显示保存失败的实际原因，保留未保存输入；950px 以下详情采用浮层避免操作被裁切。标签迁移等待分类边界确认，本迭代尚未完整交付，不提前宣称 N04 通过。

React 对话框 effect 按 Context7 查询到的官方模式调用 showModal 并在清理时 close；Playwright 坐标交互同样查询了当前官方文档。测试需允许本机监听端口，默认沙箱中的 EPERM 不算测试通过，放开本机端口后全量重跑通过。
