# v0.7.0 todo-list 技术方案

## 文档的关键结论

沿用 React、现有应用控制器和两套呈现入口，不改变工作区数据结构或服务端接口。待办仅消费 kind=day 的 placement，所有写入复用现有 save 与冲突检测。

- 增加共享待办控件及主题变量样式，两套入口增加导航并隐藏工作台布局。
- 独立纯函数生成日期分组和改期操作，禁止从 timed 推导日期；叶节点按完整任务树判断。
- 编辑与拖拽使用开始操作时的数据快照保存，失败保留错误提示；归属校验沿用领域层与标签继承规则。
- ScheduleDialog 新建定时任务时，在同一保存批次追加独立 day placement，日期取表单最终开始时间的 Asia/Shanghai 日期。仅日期创建和关联已有任务不追加；后续时段编辑与日期安排保持独立。
- 本次不修改已有 README 工作区改动。无 ROADMAP.md，不创建 PROGRESS.md。

## 边界

过期以每条日期记录早于今日且任务未完成判断；有未来日期的任务仍保留其过期日期记录。本周的过去日期不重复展示过期未完成记录。完成状态仍属于整个任务，勾选后所有日期实例同步变化，并沿用已有父子完成联动。页面筛选独立于工作台筛选，归档任务及归档分支隐藏。

## 树形概览修正

按用户最新确认，分组筛选后复用 ancestors 与 treeOrder 补齐完整祖先链，默认展开全部层级。共享祖先在每组内去重，跨日期独立保留；contextOnly 区分补出的路径节点与真实日期记录，深度决定缩进。上下文节点不为自己生成日期；后续叶节点拖拽规则允许其带动子树中叶节点日期移动。行编辑标识增加分组键，避免同一个父节点在多个组同时进入编辑。沿用 v0.7.0，不新增版本或提交。

## 直接拖拽与叶节点日期联动

移除父任务选择框及独立归属目标，任务行直接接收归属拖放并阻止冒泡。dropTodoSubtree 用完整任务树识别全部叶节点，仅改变来源日期匹配的 day 记录，合并重复目标日期；非叶节点、其他日期与 timed 不变。修改 parentId 和叶节点日期在同一 save 批次提交，保留原始快照的冲突检测。顶部拖放仅清空 parentId。未分配组拖到日期组只为无日期的叶节点分配日期；过期上下文节点以该子树在过期组的命中日期作为来源集合。

三个主题标题统一 16px，常规任务行实测 37.4px。10 项相关自动测试、类型检查和构建通过；隔离浏览器验证行归属、拖成一级、子孙随迁、跨日只改叶节点、日期去重、父节点及时间条保持、单次保存和三主题密度。改动保留在工作区，不自动提交。

树形修正验证：8 项相关测试、类型检查与构建通过；隔离浏览器确认三层祖先、搜索保留路径、跨日期独立树、编辑实例隔离、上下文节点拖拽不写入日期及窄窗布局。
