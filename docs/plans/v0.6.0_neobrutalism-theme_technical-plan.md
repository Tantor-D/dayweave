# v0.6.0 / neobrutalism-theme 技术方案

## 文档的关键结论

采用共享应用能力与独立呈现目录，沿用当前技术栈和本机服务。现有 App 同时包含状态、提交与界面，现已拆分为稳定存活的应用控制器和可替换的风格入口。

- 各风格独立拥有页面与样式，不互相导入；共享控件允许复用，但通过呈现上下文取得各自样式，不依赖玻璃样式。
- 风格入口自行组织导航和页面，不以当前 ViewLayout 三栏结构约束未来界面。
- 不引入微前端、插件运行时或任意布局配置系统。

## 实施

1. 提取应用控制器，保留同步、提交、筛选、选择和通知。相同的时间轴交互作为可选共享能力，未来不同布局可替换。
2. 将玻璃视图与样式迁入 presentations/glass；独立建立 neobrutalism 页面、布局和样式。共享控件接收样式上下文，基础全局规则仅保留重置。
3. 注册主题及当前偏好校验；不修改冻结的 legacy 校验。主题保存成功后才切换，失败保持原视图；编辑区域、弹窗、拖拽、保存期间锁定切换，避免卸载草稿。
4. 保留玻璃布局宽度偏好，新风格采用独立布局尺寸，不覆盖旧尺寸。主题 ID 保持向后兼容。
5. 更新版本与使用说明，测试和构建，隔离浏览器验收后本地提交，不推送。

## 验证

验证新旧偏好读写、非法主题拒绝；检查各风格依赖隔离及样式覆盖。公共业务运行完整测试，各风格检查页面、弹窗、主题切换与刷新、窄窗口和时间轴。产物放 .artifacts（已忽略）。仓库无 ROADMAP，不新增 PROGRESS。

## 交付结构与扩展约定

- `presentations/glass` 与 `presentations/neobrutalism` 各自拥有 Workbench 页面、布局、主题配置、工作台和统计样式；禁止家族间导入。
- `application/useWorkbench` 保持存活，提供数据同步、保存、筛选与应用状态。玻璃分隔栏交互归玻璃目录；`scheduleDrag` 是两套当前时间网格可选复用的交互，不是未来布局必须遵循的统一协议。
- Panels、Timeline、表单与统计控件本版复用，通过 Appearance 样式契约获取当前家族样式。未来布局可替换这些控件，公共层不得反向依赖具体家族。
- 切换保护采用保守锁定：详情、编辑弹窗、统计弹窗、拖拽或保存进行中不可切换；草稿未迁移到公共层，不宣称可以跨任意界面迁移编辑会话。
- 当前真实差异为玻璃可调分栏与新风格固定任务栏／独立详情浮层；不建立占位的第三到第五套界面。
