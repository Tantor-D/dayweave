# 个人专注工作台实施方案

## 文档的关键结论

本项目面向个人上班期间的任务安排、注意力管理和简短复盘，交付一个在本机运行、通过浏览器使用的工作台。本文是 `v0.1.0 / focus-workbench` 的功能实施基线；用户已于 2026-11-03 授权全部 A—E 阶段，现已完成本地实现与验收，真实模型连接仍待用户配置后验证。

- 第一版交付任务与项目管理、可拖拽时间看板、玻璃拟态深浅主题、AI 协作、反思记录及修改回溯的完整使用流程。
- 默认看到今天及未来两天；任务可以只归日期，也可以安排多个时间块；重叠数量由用户自行判断，系统不限制、不提醒。
- 本地文件是数据本体。网页和 AI 的规范写入路径共用规则校验与历史记录，harness 提供类似对象 `set` 方法的操作工具，不声称禁止本地 AI 直接编辑文件。
- AI 同时支持网页内接口和外部本地工具；长期背景与短期安排常驻可读，反思按需读取；AI 写入可配置为自动接受或必须网页确认，并保留回溯能力。

### 1.1 用户已明确的需求

- 本机网页配合本地数据目录，适合外部 AI 阅读；Git 同步只是未来可能性，不是第一版要求。
- 任务可独立存在，也可属于项目；可以调整优先级，并通过不同颜色辨认。
- 通过拖拽、拉伸安排任务，支持仅指定日期；任务列表与时间看板之间可调宽，不做任意模块自由摆放。
- 支持单日、多日和横纵时间轴，默认展示今天及未来两天；同一时段任意数量任务都可保留，不进行容量提醒。
- 可以按个人／工作等分类、项目或任务控制显示；这是普通筛选，不是老板键。
- 首发采用玻璃拟态并具备深色主题，为手帐等其他视觉风格保留扩展方式。
- AI 既可以通过网页配置的兼容接口使用，也可以由本地工具读取文件并经 harness 修改。
- AI 背景只有长期、短期两个常驻信息框；反思目录不默认进入每次上下文，但 AI 可以按要求读取和修改。
- AI 修改采用可配置的自动接受／网页确认策略，并提供回溯；复盘以计划、完成情况和简短反思为主。

## 2. 目标、场景与成功标准

### 2.1 产品目标

用户可以把脑中的事情放到任务列表中，看见近期安排，并在一个时段里自主选择当前要处理的事项。工作变化时可以快速调整，而不必重新整理整张计划表；工作结束后能回看安排、完成的事情和自己的反思。

### 2.2 核心使用场景

| 场景 | 用户行为 | 预期结果 |
| --- | --- | --- |
| 上班前整理 | 收集独立待办，将较大事项建成项目并拆任务 | 所有事情有清晰归属，不要求立刻安排具体时间 |
| 安排近期工作 | 把任务放到今天、明天或后天，再给其中一部分分配时段 | 能同时看见未定时事项和已经承诺的时间块 |
| AI 并行工作 | 给几个任务安排重叠时段，根据进展切换关注项 | 重叠布局保持可读，不阻止操作或弹出数量提醒 |
| 临时调整 | 拖动时间块、拉伸时长、修改优先级 | 调整保存可靠，不丢任务、不重复创建任务 |
| 切换工作范围 | 暂时排除个人分类或某个项目 | 页面减少干扰，底层任务与排期保持原样 |
| AI 辅助安排 | 让网页 AI 或本地工具拆解任务、建议改排 | 同一份文件数据被规范修改，可理解修改内容并回溯 |
| 下班复盘 | 查看当天计划和完成情况，写几句话 | 无需计时也能留下可供以后阅读的工作记录 |

### 2.3 第一版完成标准

用户能独立完成“创建项目／任务 → 安排日期和时间 → 调整或完成 → 写反思”的日常流程，重新启动后数据仍完整；AI 与手工修改共用数据和回溯，不出现静默覆盖或把失败显示为成功。

## 3. 功能范围与交互规则

### 3.1 工作台结构

- 左侧为任务面板，集中呈现独立任务、项目及项目内任务；中央为时间看板。
- 左右区域之间可以调整宽度；右侧详情面板可收起，用于任务详情、AI 对话与复盘，不遮挡整个看板。
- 顶部提供日期导航、今天快捷入口、单日／三日／七日切换、横纵方向、筛选和主题入口。
- 切换日期、方向或主题只改变呈现方式，不移动任务、不改变时间数据。
- 面向桌面浏览器优先设计；窄窗口允许区域收起或滚动，不将手机完整适配列为首版验收条件。

### 3.2 任务、项目与分类

- 任务具有标题、说明、状态、优先级和归属；任务说明允许普通文本或 Markdown 内容。
- 独立任务不要求创建项目。项目只负责组织，实际安排到时间看板的是任务。
- 项目属于一个分类，其下任务继承该分类；独立任务自行选择分类。移动任务到另一个项目时同步显示新的分类归属。
- 支持创建、编辑、调整归属、完成和归档；归档保留内容与历史，可恢复查看。
- 完成任务记录完成时间，保留原有排期；已完成任务在看板上使用清晰的完成样式，不自动删除未来安排。
- 任务名称和项目名称可以修改；关联关系不依赖可变名称。
- 优先级以颜色和文字共同表达，分类／项目采用辅助标签，避免两套颜色争夺同一种含义。

### 3.3 日期与时间安排

- 同一任务允许有多个安排，每次安排要么是“仅指定日期”，要么是“具有起止时间的时间块”。
- 没有安排的任务保留在任务面板；仅指定日期的安排进入当天“未定时”区域，不占满全天。
- 从任务面板拖到某日或时段时创建一次安排，不复制任务本体；再次拖入可以为同一任务增加另一段安排。
- 将已有未定时安排拖入时段时转换该安排；将已有时间块拖回未定时区域时去掉具体时刻，避免意外重复创建。
- 已有安排可以跨日期移动，时间块可以调整开始或结束；删除一次安排不删除所属任务。
- 重叠任务并排显示，不因超过两项而提示或阻止；优先保证每张卡片仍可选择和打开详情。
- 横向视图以时间为横轴、日期为纵向分组；纵向视图以时间为纵轴、日期为并排分组，两者共享同一套安排。
- 跨午夜的时间块按日期分段呈现，操作仍对应同一条安排；表单可查看完整开始和结束日期时间。
- 除拖拽外，详情表单提供日期、开始和结束的直接编辑方式；修改提交失败时恢复原显示并说明原因。

### 3.4 筛选与主题

- 支持按分类、项目、任务和状态排除或恢复显示；排除项目时一并排除其下任务。
- 筛选可以组合，重新打开工作台后保留偏好；提供清除筛选入口，避免用户误以为任务丢失。
- 筛选只控制页面显示，不删除排期，也不构成 AI 数据访问权限。
- 第一版提供玻璃拟态浅色和深色两套外观，保持文字、任务优先级和当前选中状态可辨认。
- 不把整个任务卡片做成低对比度透明色块；减弱动画和不支持背景模糊时仍能正常阅读与操作。
- 外观主题与页面布局分开扩展。后续手帐或其他玻璃风格可以替换材质、字体、间距及卡片外观，明显不同的页面结构通过独立布局接入。

## 4. AI、文件与回溯的用户流程

### 4.1 AI 使用入口

- 网页设置提供 API 基础地址、模型名和密钥输入，首版使用 OpenAI Chat Completions 兼容协议。
- 支持普通聊天的接口至少能给出文字建议；结构化修改能力不可用时明确显示限制，不把自然语言或代码块猜测成可执行指令。
- 外部本地 AI 可以直接阅读业务文件，并通过提供的 harness 操作工具修改；第一版交付通用本地命令入口和数据说明，不自动安装或配置某个外部 AI 产品。
- harness 是对任务、安排及文本操作函数的适配层，不是另建模型运行平台，也不维护另一份数据。
- 命令入口连接已经运行的本地工作台服务；服务未启动时明确提示，不另起一条直接写文件的旁路。

### 4.2 两类背景与反思

- AI 背景界面只有“长期背景”和“短期安排”两个文本框；内容由用户随时编辑或清空，不按每天建立配置。
- 网页每次请求重新加载两类背景；外部入口提供同样的背景上下文，并在使用说明中约定调用前读取。
- 网页显示本次对话使用的任务范围，默认取当前视图关联任务，可由用户扩大或调整；AI 上下文选择与看板筛选分别管理。
- 反思目录独立于两类背景。用户选择或明确指定某篇反思后，才向网页模型提供正文；不默认读取整个目录。
- AI 可以按用户要求新增反思，或修改用户指定的既有反思，也可以更新长期、短期背景；这些修改均适用 AI 写入策略和历史记录。
- AI 没有被保证“理解或遵守”所有背景；产品能保证的是按约定加载并提供这些内容。外部 AI 的直接文件访问能力由其宿主环境决定。

### 4.3 规范修改路径与确认策略

规范流程为：读取当前内容 → 调用语义明确的操作 → 校验并生成差异 → 按配置确认或自动接受 → 保存原始文件并记录历史。

| 模式 | 网页内 AI | 外部 AI harness |
| --- | --- | --- |
| 必须网页确认（默认） | 展示待确认差异，用户确认后写入 | 创建待确认提案，工作台内确认后写入 |
| 自动接受 | 校验通过且版本一致时写入，并展示结果 | 校验通过且版本一致时写入，返回结果与历史编号 |

- 用户手工进行的正常界面编辑直接保存，不因 AI 策略增加重复确认。
- 自动接受只省略人工确认，不跳过数据校验、冲突检测和历史记录；以提交时的最新策略为准。
- AI 不能自行更改确认策略、接口密钥或授予自己更高权限；这些设置由用户在工作台管理。
- 提案展示实际修改前后的内容，而不是仅显示 AI 自己撰写的解释。
- 一份提案以一个工作数据文件或一篇 Markdown 文档为修改单位；跨文档请求分成多条提案，各自显示待确认、成功、冲突或失败。有依赖的后续修改等待前置修改成功。
- 本地 AI 物理上仍能直接编辑文件。此路径属于规范入口之外的手工维护，不天然拥有同等的校验、审批和历史链；产品不能把未经过入口的改动伪称为“已审批”。
- 检测到外部直接修改时，先检查内容并展示差异，由用户显式采纳；非法内容不替换应用已知的有效状态。

### 4.4 修改历史与恢复

- 历史列表显示时间、修改来源、目标、摘要和确认方式，可以查看前后差异。
- 支持撤销最近一次已提交的修改，以及选择历史版本、预览影响后恢复。
- 恢复生成新的修改记录，原来的历史继续保留；版本不会倒退。
- 项目、任务和排期共同保存为工作数据快照。恢复该快照可能同时影响多个任务，界面必须明确范围，不能呈现成仅撤销某个任务的按钮。
- 恢复 Markdown 文档只影响对应文档；工作数据与不同文档的历史不混淆。
- 确认前数据被其他操作修改时，显示冲突并要求更新预览，不静默覆盖较新的内容。

## 5. 复盘与异常体验

### 5.1 日常复盘

- 选择日期后，可以查看该日安排的任务、这些任务当前的完成状态，以及历史完成事件发生于该日的任务；后来重新打开任务时仍保留曾经完成的记录。
- “当天完成”按完成记录判断，不把当天所有已安排时间视为完成；计划时长不作为实际投入时长统计。
- 每日可选写几句话，也可另建独立命名的总结反思；不强制填写模板或每天提交。
- 复盘页面明确区分计划与完成，不生成效率评分，不要求持续计时。

### 5.2 异常与空状态

- 首次打开无任务时给出新建任务与可选示例入口，不自动填入模拟业务数据。
- 筛选后为空时提示当前筛选状态并允许清除，不误导为数据已删除。
- 模型超时、取消或返回无效修改时保留已有内容，给出可重试的原因，不能显示“已应用”。
- 文件损坏、写入失败或存在版本冲突时保留可恢复内容，界面不继续把未保存的状态当作已保存。
- 关闭并重开程序后，任务、排期、两类背景、反思及偏好仍可读取。

## 6. 实施阶段与交付边界

以下阶段属于同一个 `v0.1.0 / focus-workbench` 迭代，不分别递增版本。本次已获功能实现、本地运行与验收授权，不包含推送或云端部署。

| 阶段 | 工作重点 | 阶段完成标志 |
| --- | --- | --- |
| A：数据与操作基础 | 文件模型、规范操作入口、版本检查、历史与恢复 | 能通过统一入口操作样例数据，错误输入和过期修改被拒绝，重启与恢复有效 |
| B：任务与看板 | 任务面板、项目分类、优先级、日视图及三／七日视图、拖拽拉伸 | 核心手工安排流程完整，横纵视图一致，任务与安排不会混淆 |
| C：个人工作空间 | 玻璃深浅主题、区域调宽、筛选、背景与反思编辑 | 偏好持久化，切换外观不影响数据，日常复盘可独立完成 |
| D：AI 协作 | 兼容接口、上下文选择、结构化提案、可配置确认及外部命令工具 | 网页 AI 和外部工具修改同一份数据，遵守统一策略并可回溯 |
| E：验证与使用交付 | 集成验证、真实浏览器操作、启动与数据维护说明 | 验收矩阵通过，已知限制明确，一条命令可启动正式本地服务 |

本次交付范围为阶段 A 至 E 的完整本地实现；实际验证结果在交付会话与已忽略的运行产物目录中记录，不以计划内容代替测试结果。

### 6.1 第一版不包含

- 云托管、登录、多用户协作、多设备同步及自动 Git 同步。
- 循环任务、外部日历同步、通知提醒、实际工时计时或效率评分。
- 无限嵌套任务、任意模块自由排布、完整手机交互适配。
- 首发以外的完整手帐等主题、第三方主题市场或插件平台。
- 特定 AI harness 的安装、产品专属插件或 MCP 适配；第一版提供通用工具路径，后续按使用方式讨论接入。
