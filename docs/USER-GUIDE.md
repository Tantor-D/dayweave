# 使用与维护指南

## 文档的关键结论

留白在本机浏览器运行，任务和偏好保存为 JSON，背景和日记保存为 Markdown。本文集中说明日常操作、启动开发、数据备份与恢复；产品概览见 [README](../README.md)，AI 操作规则见 [AI 协作指南](AI-USAGE.md)。

- 默认访问 `http://127.0.0.1:4310`，同一数据目录只运行一个服务实例。
- AI 修改先预览、再确认；备份时先关闭服务，并保留配套本机状态目录。
- 当前版本为 `v0.5.0 / cli-ai-workflow`，设计见 [功能计划](plans/v0.5.0_cli-ai-workflow_functional-plan.md) 和 [代码开发方案](plans/v0.5.0_cli-ai-workflow_technical-plan.md)。

## 启动与开发

需要 Node.js 22.12 或更新版本，以及 npm。进入本项目目录后：

```sh
npm ci
npm run build
npm start
```

浏览器打开 `http://127.0.0.1:4310`。第一次构建后，平时只需 `npm start`；按 Ctrl+C 关闭。端口冲突时明确报错，可指定其他端口和独立的绝对数据目录：

```sh
npm start -- --port 4320 --data-dir /absolute/path/focus-data --local-dir /absolute/path/focus-local
```

每个数据目录应配套独立的本机状态目录；本机状态目录必须在数据目录之外。同一数据目录只允许运行一个服务实例；不要手工删除仍在运行的服务的写入锁。

开发模式同时启动 Vite 和本地 API，访问 `http://127.0.0.1:5173`：

```sh
npm run dev
npm run typecheck
npm test
```

开发模式 API 默认使用 4310 端口，可通过 `PORT` 环境变量同步调整服务和代理，不能同时再运行另一个相同端口的 `npm start`。前端热更新，后端源码变更后需重启开发命令；后端启动失败会一起停止前端。生产页面由 Fastify 提供，Vite preview 不用于正式启动。

## 日常使用

1. 新建根任务或搜索未完成的父任务创建子任务，也可将左侧任务拖到另一个任务上调整归属，子任务可继续嵌套。标签可多选或不选，预置 P0–P4；在“标签管理”新增自定义标签，名称禁止包含 "/"。标签可配置颜色与颜色优先级，数值越小越优先；多标签按优先级取色，完成后淡化。
2. 在时间轴空白处按住左键拖选、松开打开安排面板，Esc 取消；单击默认一小时。把任务拖到某天的未定时区域，只安排日期；拖到时间轴生成默认一小时的时间块。已有安排可拖动和从两端拉伸，按 15 分钟吸附；Esc 取消拖拽。
3. 详情表单可直接编辑日期和分钟级起止时间、增加多个安排或删除某一个安排。删除安排不会删除任务。
4. 切换单日、三日、七日或横纵方向；标签、任务树节点和状态筛选仅控制显示。重叠不限制、不提醒。
5. 完成父任务会完成全部后代；所有子任务完成时父任务自动完成。重新打开子任务时祖先自动变为未完成；子任务全部完成的父任务需先重新打开一个子任务。原排期保留。复盘区分计划与真实完成事件，重新打开任务不抹去曾经完成的历史。反思可按日保存，也可创建独立笔记。
6. 背景区分别保存长期背景和短期安排。历史中查看真实前后内容，预览恢复后执行；恢复整个工作区会影响其中整个任务树、标签和排期。

左侧“全部／今天／本周／未来三天／未来七天”按排期筛选，未来范围包含今天，本周从周一开始，必要祖先作为层级上下文保留；中央看板仍使用自身日期范围。未排期任务仅在“全部”中直接展示。

“设置”中的每天开始／结束时间默认为 10:00–21:30，仅改变显示与拖选，范围外排期不会被删除。横向单日行上限 284px，左右分别内部滚动；纵向未定时区上限 144px。

子任务复制继承父标签默认开启，可在设置关闭。新建或换父任务时复制，之后可独立修改，不反向影响父节点。父任务标签变化时选择仅此任务或应用全部后代；批量应用合并父任务当前标签，并移除本次从父任务删除的标签，保留后代其他标签。取消弹窗不会保存。

页面设置可切换玻璃浅色／深色主题；面板分隔线可拖动调宽。偏好保存到本地文件。可选的体验示例通过正常操作入口创建，会成为真实数据并留下历史，可以通过该次历史恢复撤销。

## AI 与外部工具

在项目目录启动 Codex，依照根目录指令使用 harness 连接正在运行的本机服务。模型由 CLI 自身的登录和额度管理，工作台不配置或调用模型，不读取旧 `.local/secrets.json`，也不自动删除它。

```sh
npm run --silent harness -- context
npm run --silent harness -- documents
npm run --silent harness -- proposals
```

AI 可以检索全部工作台日记并按需读取正文；写入先生成提案并展示真实差异，你在聊天确认后调用 confirm。服务端信任 CLI 识别确认，仍校验来源、版本和历史；普通 submit 不再自动接受。网页也可确认或拒绝待确认提案。

详细命令、授权边界和其他 CLI 适配见 [AI 与 harness 使用说明](AI-USAGE.md)。

## 文件、备份与恢复

| 位置 | 内容 |
| --- | --- |
| `data/workspace.json` | 唯一工作数据真源：任务树、标签、排期及 revision（schemaVersion 3） |
| `data/preferences.json` | 主题、视图、筛选、面板宽度、每日显示时间和标签继承开关 |
| `data/ai/long-term.md`、`short-term.md` | 两类常驻背景 |
| `data/reflections/daily/`、`notes/` | 每日与独立反思 |
| `data/.history/changes/` | 完整前后内容、来源、审批和恢复记录 |
| `.local/` | 模型密钥、工具凭据、持久化提案、请求去重及最近有效保护快照 |

v2 数据升级时将进行中转为未完成，并补齐标签颜色及颜色优先级；升级启动也会把 v1 项目迁移为根任务、原项目任务转为子任务，将旧分类及优先级转为普通标签。原始工作区备份保存在 `data/.history/changes/workspace-v<旧版本>-<hash>.backup`，并生成迁移历史；原历史不重写，恢复旧快照时自动转换为新模型。旧标签名称中的 "/" 转为全角 "／"。有未采纳外部修改时不会自动覆盖；旧工作区待提交提案需重新生成。

数据与 `.local` 默认被 Git 忽略。备份时先关闭服务，再一起复制数据目录和配套 `.local`；后者包含密钥，应按私人文件保管。程序不自动清理历史，不执行同步或数据 Git 操作。

本地用户和 AI 仍可直接编辑原始文件。harness 是规范 setter，不是物理封锁；直接编辑后，网页展示外部差异并等待采纳或恢复。采纳必须通过格式与关系校验，记录来源为外部导入。应用只保证规范写入及显式采纳的最终外部版本可回溯，不保证捕获外部连续直改的每一个中间版本。

损坏或未知 schemaVersion 的文件不会触发空数据覆盖。提交中断时重启会核对 prepared 历史和实际文件；结果不明时保留现场、停止该目标写入。不要在出现故障时删除历史和本机保护快照。新建 Markdown 的“恢复修改前”保留一个空文档，其旧内容仍保留于历史。

## 验证与边界

自动测试及浏览器验收使用隔离临时数据，不读取真实业务数据或调用付费模型。Codex 为正式验证入口；Claude Code、Gemini CLI 的兼容指引不代表已完成实机验收。

首版为桌面本机单用户使用，不包含手机完整适配、循环任务、提醒、实际工时计时、多设备同步、云服务和特定 AI 产品的 MCP 适配。时区固定为 Asia/Shanghai，时间块保存为 UTC。

功能与工程设计依据保留在 [功能方案](plans/v0.1.0_focus-workbench_functional-plan.md) 和 [技术路线](plans/v0.1.0_focus-workbench_technical-plan.md)。
